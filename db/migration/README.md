# db/migration

이미 만들어진 DB 위에 차례로 실행하는 변경 SQL(ALTER 등)만 둔다. 사람이 직접 실행한다.

- `db/` 바로 아래 파일(`*_create_tables_*.sql`, `*_insert_com_cd_*.sql`)은 처음부터 새로 만드는 기준 파일이다. 전체를 DROP하고 다시 만들므로 공용 DB에는 실행하지 않는다. 공용 DB에는 이 폴더의 파일만 실행한다.
- 파일 이름은 `YYYYMMDD_NN_설명.sql`이다(예: `20261022_01_add_expnd_idmpt_dmnd_id.sql`). `NN`은 같은 날짜 안의 순번이고 01부터 시작한다. 이름 순서가 실행 순서다.
- 병합된 파일은 고치지 않는다. 바꿀 것이 있으면 새 파일을 추가한다.
- 파일 맨 위 주석에 무엇을 왜 바꾸는지와 근거(문서·기능 ID)를 적는다.
- 실행할 때 오류가 나면 거기서 멈춘다. DBeaver는 스크립트 실행에서 오류가 나도 계속하는 설정이 있으니 끈다. MySQL DDL은 롤백되지 않는다.
- 공용 DB 적용 기록은 이 폴더에 두지 않는다. PR 작성자가 병합 직후 공용 DB에 실행하고 PR에 완료 댓글을 남긴다(`docs/convention/shared-files.md`).
- 기준 파일을 새 버전으로 낼 때는 그때까지의 이 폴더 파일을 기준 파일에 합친다.
